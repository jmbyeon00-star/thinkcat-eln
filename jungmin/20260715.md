## 확정 플로우 (오늘 기준 최종)

```
raw_text → base_id = "txt_" + md5(raw_text)[:16]
  ↓
① check_subscription(db, user_id)
  - expired_trial / expired_subscription → SSE error return
  - ok → org_id 획득
  ↓
② INVAL_TEXT_CACHE_TB에서 base_id 확인
  │
  ├─ 캐시 없음 (완전 새 텍스트):
  │    → check_credits  ← LLM 호출 전에 먼저 확인
  │    → GPU /prepare  (LLM refine + Neo4j 15개)
  │    → INVAL_TEXT_CACHE_TB 저장  (refined_text, refined_title 만, Neo4j 결과 저장 X)
  │    → 파이프라인 (앵커 → 파싱 → 임베딩 → 쌍별 → 종합)
  │    → INVAL_HISTORY_TB 저장 (result_json에 candidate_patents 15개 포함)
  │    → decrement_credit
  │
  └─ 캐시 있음 (이전에 누군가 올린 적 있는 텍스트):
       → refined_text 로드 (LLM 불필요)
       → asyncio.gather(                          ← 병렬 실행
            GPU /refresh (Neo4j fresh 15개),
            get_org_history(db, org_id, base_id)  ← DB 조회 동시에
         )
       → new_top5 = similar_app_numbers[:5]
            │
            ├─ 히스토리 없음:
            │    → check_credits → 파이프라인 → INVAL_HISTORY_TB 저장 + decrement_credit
            │
            └─ 히스토리 있음:
                 → set(new_top5) vs set(history.prior_app_numbers) 비교
                      ├─ 같음 → result_json 그대로 반환 (무료, 추가 GPU 호출 없음)
                      └─ 다름 → check_credits → 파이프라인 → history UPDATE + decrement_credit
```

**핵심 원칙:**
- Neo4j 결과는 절대 DB 캐시 안 함 (항상 fresh)
- LLM refine 결과만 캐시 (`INVAL_TEXT_CACHE_TB`)
- 크레딧 check는 LLM/파이프라인 호출 직전에 (비용 발생 전에 막기)
- 크레딧 decrement는 파이프라인 완료 직후

#### 3-5. refresh 엔드포인트 재작성

```
1. check_credits(db, org_id)   ← check_subscription 불필요 (스케줄러 보장)
2. InvalHistoryDB에서 history 조회
3. InvalTextCacheDB에서 refined_text 로드
4. GPU /refresh → new_prior_app_numbers
5. set(new) == set(old) → {changed: False} 반환 (무료)
6. 변화 있음 → 파이프라인 (앵커 old_result에서 재활용, 선행발명 GPU fresh)
7. update_history + decrement_credit
```
